# v2.2.0 · 入口生命周期：manifest 溯源与安全卸载

对应 issue #15。本文记录决策链路与否掉的备选；完整改动见 `CHANGELOG.md`。

## 问题

入口安装脚本在跨版本重装时会把备份覆盖成 Guard shim 自己，原始入口从此不可追溯。

### 引入点

`v0.2.3` 时备份后缀是写死的：

```bash
BACKUP_SUFFIX="${CLAUDE_GUARD_BACKUP_SUFFIX:-bak-before-claude-guard-v0.2.2}"
if [ -e "$target" ] && [ ! -e "$backup" ]; then cp -p "$target" "$backup"; fi
```

名字稳定，所以 `[ ! -e "$backup" ]` 这个守卫是**正确的**：第二次安装会发现备份已存在，
跳过。

`v1.0.0`（`326e532`）把后缀改成插值版本号：

```bash
PROJECT_VERSION="$(tr -d '[:space:]' <"$ROOT_DIR/VERSION")"
BACKUP_SUFFIX="${CLAUDE_GUARD_BACKUP_SUFFIX:-bak-before-claude-guard-v${PROJECT_VERSION}}"
```

守卫条件一个字没动。它本来为「稳定文件名」而写，名字变成版本相关之后就**静默失效**
了——改了 A 的假设，没有检查依赖该假设的 B。

影响面：`v1.0.0` 之后在两个以上版本上跑过入口安装脚本的用户。项目此后发过 7 个版本。

### 三层缺陷

1. **跨版本重装产生假备份**。第二次安装时 `$backup` 是新名字、不存在，于是把当前
   target（此时已是 shim）复制进去。升级 N 次就有 N 份备份，**只有第一份是真的**。
2. **`cp -p` 展平 symlink**。原入口若是 symlink（npm 全局安装的典型形态），备份变成
   普通文件，链接关系永久丢失。
3. **悬空 symlink 被 `[ -e ]` 漏掉**。`[ -e ]` 为假而 `[ -L ]` 为真，于是**连备份都
   不做**就被 `install` 覆盖。

第 1 条最危险的地方不是多出几个文件，而是它会**骗过卸载器**：按「恢复最新备份」这个
最自然的直觉写出来的卸载器，会把 shim 恢复成 shim，看起来成功，实际什么都没退；若此
时 `claude-guard` 已被删除，恢复出的入口还会 exec 一个不存在的文件。

## 决策

### 用 manifest 记录，而不是靠文件名编码信息

`~/.local/share/claude-guard/entrypoints.json` 记录每个入口被接管**之前**的状态。

**核心不变式：`original` 一旦写入就永不覆盖。** 重复安装只刷新
`artifact_sha256` / `guard_version` / `installed_at`。这条不变式就是本 bug 的根治点
——旧实现把「要不要重新采集原状态」这个判断挂在了文件名上，而文件名会随版本漂移。

否掉的备选：**继续用文件名、只是改回稳定后缀**。这能修第 1 条，但修不了第 2、3 条
——symlink 和悬空 symlink 的信息根本无法用「复制一个文件」表达。而且它把状态编码在
文件名里，下一次有人想加一个维度时还会重蹈覆辙。

### symlink 只记 target，不复制文件

`state` 有四种：`absent` / `file` / `symlink` / `dangling-symlink`。只有 `file` 才
`cp -p` 到 `<入口>.claude-guard-backup`，symlink 与悬空 symlink 一律只把 `readlink`
的结果记进 manifest，恢复时用 `ln -s` 重建。从源头绕开展平问题，悬空 symlink 也能原样
重建。

状态判定里 `-L` 必须排在 `-e` 前面，否则悬空 symlink 会落进 `absent` 分支。

### shim 判定：重建后逐字节比对，不做模糊匹配

新 shim 正文加一行 `# claude-guard-shim 1` 标记。但判定不止看标记：shim 正文由 guard
路径唯一决定，因此可以从文件里读出 guard 路径、重建完整正文、逐字节比对。同时保留对
`v2.1.3` 及更早那版 4 行无标记 shim 的识别——`--inspect` 必须能在**没有 manifest 的
存量环境**上工作，那正是最需要它的场景。

否掉的备选：**只 grep `exec ".*claude-guard"`**。太松，任何一行包含它的文件都会被当成
shim，而这个判定的下游动作是删除文件。

### 卸载全程 fail-closed，且分两遍

第一遍只校验不动文件，全部通过后才进入第二遍执行。理由：**恢复到一半的入口比不恢复
更难排查**。任一前置条件不满足即 `exit 14`，一个文件都不动。

其中一条检查是「备份内容本身是不是 Guard shim」——它专门用来接住 issue #15 已经在存量
用户机器上留下的现场。

### 存量迁移必须由人指认

`--inspect` 只读列出每个入口现状、找到的所有历史备份，并逐个判定「是真原件还是 shim」。
`--adopt-backup <名称>=<路径>` 让用户显式指认，指认时再校验一次它不是 shim。

**历史备份一律不自动删除**，包括用户指认的那一份。判断哪个是真原件需要人来看，脚本
不替用户删——这个 bug 本身就是「脚本自作主张地认定某个文件是什么」造成的。

否掉的备选：**卸载时自动挑一个非 shim 的备份**。看起来聪明，但如果有两个非 shim 备份
（比如用户自己也备份过），它会静默选错，而这次的错误后果是覆盖用户的 `claude` 命令。

### 卸载范围包含 Guard 自身

恢复入口之外，也移除 `~/.local/bin` 下的 `claude-guard` 与 `claude-cc` 以及 manifest。
每个文件先按哈希核对确认是我们装的那一份，不匹配就 fail-closed 保留。否则「卸载」名不
副实，用户还得自己去删。

## 教训

- **改掉一个变量的性质时，要回头检查所有依赖其旧性质的判断。** 后缀从常量变成版本相关
  只是一行改动，但它让另一处 `[ ! -e ]` 从正确变成错误，而那一处一个字都没动。
- **把状态编码进文件名，迟早会因为文件名的构成规则变化而崩。**
- **`[ -e ]` 不是「文件存在」，是「路径可解析」。** 悬空 symlink 会让它为假。
- **bash 3.2 会把紧跟在 `$var` 后的多字节字符首字节吞进变量名**，`set -u` 下报出
  `path?: unbound variable` 这种无法索解的错。bash 5 没有这个行为，ShellCheck 也不报，
  因此只有 macOS 上才会炸。本仓库几乎全是中文提示语，这个坑一碰一个准。已在
  `tests/smoke.sh` 加了一条全仓 lint 永久拦截，写成 `${var}` 即可。
- **变红但没有输出的测试等于没有测试。** 本次实现中一条变异确实让用例失败了，却因为
  安装脚本的输出被重定向进文件、`set -e` 又不打印任何东西，现场完全沉默。已改为失败时
  主动打出日志。

## 边界

- 不改变任何 fail-closed 条件、既有退出码、路由、网络探测或 watchdog 行为。
- 不触碰 `bin/claude-guard` 与 `bin/claude-cc`。
- 不自动清理历史备份。
